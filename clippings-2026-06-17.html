1Claude Code = Insane Custom Websites FAST

主題：Higgsfield MCP + Figma Dev Mode 在終端內生成網站與 AI 影像資產

一句話：把 Figma 設計、AI 影像/影片生成、部署全收進 Claude Code，「不切換開發環境」做出含動態資產的網頁。
在講什麼

用 Figma Dev Mode 的 MCP 把真實 CSS/React 程式碼（不是截圖）丟給 Claude，再用 Higgsfield MCP 直接在終端生成 16:9 背景、產品圖、10 秒影片，一站完成設計到部署。

學到什麼
  • Figma Dev Mode + MCP＝把設計稿原始碼直接導入，網頁結構貼合原設計
  • 「一次一個 section、由上而下」做，避免 context window 失準
  • Nano Banana Pro 用特徵參考維持角色/產品視覺一致；Seedance 把靜圖轉 10 秒 16:9 影片
  • 實用指令：把圖轉透明 PNG、collapse nav 成漢堡選單、推上 GitHub 並走 Cloudflare Pages
能怎麼運用
  • 客戶報價/提案系統的展示頁，用這套 MCP 流程快速做品牌級 landing
  • App 行銷頁與素材生成（角色一致性 + 動態背景）
  • 作品集頁：用 AI 動態資產做沉浸式呈現
跟現有主題知識的關係
互補

補進 前端設計與Screenshot Loop：新增「MCP 資產生成 + Figma Dev Mode」一節；MCP 設定面可連到 MCP 機制與常用 server。

2Build $10,000 Websites using Claude Code

主題：用「設計干預」把 AI 從模板生成器變成高價量身網站

一句話：$10K 網站的差別不在程式碼量，在品味、實質、感知品質——靠安裝設計護欄 + 高品質 brief + 打磨 pass 做出「昂貴感」。
在講什麼

從「工具使用者」升級成「數位建築師」：用官方 Frontend Design、UI/UX Pro Max 等 skill 當設計護欄，避免 AI 滑向平庸；再用意圖導向指令做 QA 打磨。

學到什麼
  • 八大支柱：觀點/排版/色彩、層次/圖像/文案、動效/行動端/隱形細節
  • 裝 skill 拉高審美：Frontend Design 過濾 Inter、UI/UX Pro Max（57 風格 / 95 配色）
  • 字體換 Fraunces（標題）+ Geist（內文）；文案走節制（「Six dishes, one fire」）
  • 打磨指令：「讓這區塊更昂貴精緻」會加膠卷顆粒、延遲隨動光暈（lagging motion）
  • 部署陷阱：壓縮要選「資料夾內所有檔案」而非整個資料夾，否則路徑多一層載入空白
能怎麼運用
  • 接案/自用網站時，把「設計護欄 skill + 打磨 pass」當標準流程，產出穩定拉高
  • 成本 ~$70 對應客戶價值結構，可作為對外服務的報價邏輯參考
  • 「延遲隨動」「節制文案」直接套用到任何品牌頁的質感升級
跟現有主題知識的關係
互補

補進 前端設計與Screenshot Loop「設計護欄 / skill 清單 / 打磨指令」段；字體與文案節制可獨立成一個可重用 checklist。

3Claude Code + Google AI Image Gen：Apple 風格網頁

主題：用「影格序列」模擬 3D 產品互動，無需 WebGL

一句話：把 AI 生成影片用 FFmpeg 拆成 PNG 序列，靠 scroll/hover 切換影格，假裝 3D，20 分鐘做出 Apple 質感互動頁。
在講什麼

核心是「以影格序列模擬 3D 空間互動」而非寫 3D 引擎：Nano Banana 生起始/結束圖 → Kling 3.0 補間成影片 → FFmpeg 拆 100 影格 → JS 把捲動進度映射到影格索引。

學到什麼
  • 資產管線：Mobbin（參考）→ Claude Design（骨架）→ Higgsfield/Nano Banana（圖）→ Kling（影片）→ FFmpeg（序列）→ Vercel
  • 提取 ~100 影格達到 60fps 般捲動順暢；`ffmpeg -i in.mp4 -vf "fps=30" out%03d.png`
  • 互動邏輯＝交互狀態映射到預載影格陣列索引（hover/scroll 雙向同步）
  • 微調：影格太慢就 snappier 化、背景色差用 mix-blend-mode、首尾跳動檢查兩圖比例一致
能怎麼運用
  • 硬體/產品展示頁：用影格序列做產品旋轉、開箱式互動
  • App 功能展示，免 3D 引擎也能做高質感動效
  • 把 FFmpeg 影格化做成一個可重用 skill
跟現有主題知識的關係
互補

補進 前端設計與Screenshot Loop：新增「影格序列模擬 3D / FFmpeg 資產管線」技法，跟既有截圖回饋迴圈互補。

4How I Built INSANE Claude Design Websites In 10 Minutes

主題：Claude Design → Claude Code → Next.js + GSAP 的一鍵流程

一句話：用品牌設計系統 + claude.md 藍圖，把 Claude Design 原型一鍵轉成含 GSAP 動畫的 Next.js 5 頁網站。
在講什麼

三要素交集：品牌規範（getdesign.md 的 68 品牌）、佈局結構（Dribbble 截圖當骨架）、指令藍圖（claude.md 當唯一事實來源），10 分鐘出可上線網站。

學到什麼
  • claude.md 是「系統提示詞藍圖」＝防止 AI 設計幻覺的唯一事實來源
  • Claude Design 的 Comment / Draw＝對話式迭代修正，取代手動 CSS 偵錯
  • 關鍵 prompt 加「without it looking cheesy」讓 GSAP 動畫保持商業重量感
  • 上線前必做：占位符（Jonas Mercer）全局替換、配自定義網域
能怎麼運用
  • 需要快出高保真提案頁時的標準流程（MVP / 行銷頁）
  • getdesign.md 跟你已有的 awesome-design-md 品牌風格庫可互相對照
  • claude.md 藍圖寫法直接呼應你正在累積的 CLAUDE.md 撰寫原則
跟現有主題知識的關係
互補

補進 前端設計與Screenshot Loop（Claude Design→Code→Next.js+GSAP 流程）；claude.md 藍圖部分連 CLAUDE.md撰寫原則。與第 1-3 篇同屬「AI 建站」主題，建議在前端筆記裡開一個「AI 建站工作流」彙整段一起收。

5Claude + Nano Banana：社群內容系統

主題：用品牌系統 + JSON Prompt 量產一致性社群內容

一句話：平庸 AI 內容的問題不是工具，是缺系統——用 Identity Stack + JSON Prompt 把品牌 DNA 封裝成可複用的內容產線。
在講什麼

「圖像工具看見像素，Claude 看見意圖」：靠品牌身份堆疊（色碼/受眾/語氣）和 JSON 結構化 prompt，讓 Claude 管理敘事節奏、負空間、視覺隱喻，產出不可複製的輪播內容。

學到什麼
  • 三層框架：L1 直接轉換 → L2 品牌化 Identity Stack → L3 敘事能量整合（節奏檢核）
  • JSON Prompt 當「數據橋樑」把視覺風格 API 化，避免自然語言模糊
  • 批次產 20-30 張 B-roll 背景，建立數週用的獨家視覺庫
  • IG 輪播：1080×1350、7-10 張、發布加音樂進 Reels 演算法流（互動 +30%、3 倍曝光）
能怎麼運用
  • App / 品牌社群行銷產線：建一次 Identity Stack，後續穩定量產
  • 個人品牌的 IG 內容，用 JSON Prompt 維持視覺一致
  • JSON Prompt 工作流可抽象成 skill，跨專案重用

6I Turned Claude Opus 4.8 Into My Entire AI Operating System

主題：四 C 架構 + 漸進式授權，把 AI 從對話變持久系統

一句話：從「瀏覽器對話」轉到「編輯器 + 本地檔案系統」，用 Context/Connections/Capabilities/Cadence 四層蓋出可自動化的 AIOS。
在講什麼

模型只是引擎、你的數據是燃料、工具可替換；核心是本地檔案系統。按四 C 層級循序建構，並用「單車法」分階段把權限交給 agent。

學到什麼
  • 四 C：Context（claude.md/逐字稿）→ Connections（API/MCP）→ Capabilities（skills）→ Cadence（自動化）
  • 每天更新 claude.md＝「儲存遊戲進度」；`/insights` 產 HTML 報告找自動化機會
  • 單車法四階段：手貼數據 → 只讀+人工確認寫入 → 監看獨立執行 → 全自動
  • 安全教訓：別把高風險能力（如發信）交給未驗證的 agent（曾誤發 15 萬訂閱者）
  • 技能逆向工程（推薦）：先手動做成功，再讓 AI 回顧封裝成 skill；Session Handoff 五要素交接
能怎麼運用
  • 你的 Obsidian + Claude 系統正是 AIOS 雛形，四 C 可當體檢框架補齊缺的層
  • 「單車法」對應漸進授權思路：先唯讀、再人工確認寫入、最後才自動
  • Session Handoff 可做成 skill，解決長對話 context 混亂

7Stop Using Claude Code Without an Agentic OS

主題：把「拉霸機式」隨機使用系統化成代理作業系統

一句話：停止隨機下指令——用「領域→技能→自動化→架構」四階段，把 Claude Code 變成可追蹤、可交付的系統資產。
在講什麼

三支柱：Architecture（領域拆解 + 技能編碼）、Memory（Obsidian markdown 當輕量 RAG）、Observability（headless `-p` + 視覺化儀表板），讓非技術成員也能一鍵啟動技能。

學到什麼
  • 演進四階段：Workflows → Skills → Automations → Architecture
  • 99.9% 的人不需要向量資料庫，純 Markdown 結構對 Claude Code 已足夠且省 token
  • 建議 Vault 結構：raw / wiki / content / projects / ops / archive / personal
  • claude.md 要含「記憶地圖」讓 Claude 用最低 token 精準定位資訊
  • headless 模式（`-p`）把技能封裝成一鍵按鈕；追蹤 5 小時/週 token 用量
能怎麼運用
  • 「記憶地圖省 token」正好呼應你想用索引降低探索 vault token 的目標
  • raw/wiki 分層可對照你現有的 Clippings→主題知識→outputs 複利循環
  • headless `-p` 儀表板＝每日簡報 / 排程機制可延伸的方向
跟現有主題知識的關係
互補與第 6 篇重疊

高度相關 Obsidian+Claude AI OS架構 與 Claude Token 效率策略（記憶地圖省 token）；遞歸 Skill Creator 連 Subagent建立與使用。與第 6 篇合併處理最有效率。
